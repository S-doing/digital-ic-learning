# AXI4-Full 接口写控制器（write_data2fifo）

## 1. 模块简介
本项目实现了一个**标准 AXI4-Full 协议的写控制器（Master）**。
模块负责将外部传入的 128 位数据（拆分为 4 个 32 位数据），通过 AXI4-Full 协议的突发传输（Burst）机制，写入到带有 AXI4-Full 从机（Slave）接口的 FIFO IP 中。

主要特性：
- 严格遵循 AXI4-Full 协议的 AW（写地址）、W（写数据）、B（写响应）三通道独立握手规则。
- 支持突发（Burst）传输机制，单次突发长度为 4（`awlen = 3`，即 4 个 32-bit 数据）。
- 突发类型为递增模式（INCR），每个数据自增 4 字节。
- 状态机清晰地处理了数据拼接、`wlast` 时序以及写响应回执。

## 4. 内部结构与工作原理

- **状态机设计**：
  - `S_IDLE`：等待 `write_en` 触发，准备好 AW 通道的地址、长度等信息。
  - `S_AW`：拉起 `awvalid`，等待 `awready` 握手成功，成功后加载第一个数据。
  - `S_W`：拉起 `wvalid` 开始连续发送数据。利用计数器 `w_data_cnt` 选择 `user_data` 的对应切片，当发到第 4 个数据时精准拉高 `wlast`。
  - `S_B`：数据发完后，拉起 `bready` 等待从机返回 `bvalid`，握手成功后回到 IDLE。
- **数据切片提取**：使用 `user_data[w_data_cnt * DATA_WIDTH +: DATA_WIDTH]` 动态切片，将 128 位扁平数据精准拆分为 4 个 32 位数据发送。
- **IP 内部闭环处理**：因为使用的 FIFO IP 为全双工架构，即使只做写入，其内部的 M_AXI（输出端）也必须能够消费数据，否则内部状态机会死锁不返回 `bvalid`。因此在例化时对 M_AXI 的 `ready` 等信号进行了拉高或伪造处理。

## 5. AXI4-Full 握手协议
- 所有通道（AW/W/B）的握手均遵循 `valid && ready` 同时为高的规则。
- 一旦 `valid` 拉高，必须保持数据不变，直到对应的 `ready` 拉高完成握手，才能撤销 `valid`。
- `wlast` 信号是突发传输结束的标志，必须严格与最后一个数据在 W 通道上同拍出现。

## 6. 仿真验证说明

`write_data2fifo_tb.v` 对写控制器进行了基础功能验证：
- **时钟频率**：50MHz（周期 20ns）。
- **输入数据**：`128'h44444444_33333333_22222222_11111111`。
- **测试流程**：复位释放后，给入一个周期的 `write_en` 脉冲，等待模块执行突发写入。

| 测试项 | 检查点 |
|--------|--------|
| 地址握手 | `awvalid` 与 `awready` 是否成功握手，`awlen` 是否为 3 |
| 数据突发 | `wvalid` 是否连续保持高电平 4 拍，`wdata` 依次输出 11111111 -> 22222222 -> 33333333 -> 44444444 |
| 末尾标志 | 在输出 44444444 的同一拍，`wlast` 是否精准拉高 |
| 写响应 | 数据发完后，`bready` 拉高，`bvalid` 是否成功反馈，状态机是否回到 0 |

## 7. 已知问题与扩展限制
- **突发长度固定**：当前代码写死了突发长度为 4（`awlen = 3`）。若需支持任意长度，需要引入外部动态配置参数或修改端口输入 `burst_len`。
- **IP 版本兼容**：代码中的 `fifo_generator_0` 端口可能因 Vivado 版本或 IP 配置不同而存在微小差异（如是否带复位、是否独立时钟），连接时需与 `.veo` 模板严格对齐。
- **M_AXI 侧处理**：当前采用了硬接线伪造 M_AXI 接收。在真实工程中，建议将 M_AXI 接口引出，连接真实的 AXI 接收模块（如 BRAM Controller）或直接使用 Native 接口的 FIFO 以避免资源浪费。
