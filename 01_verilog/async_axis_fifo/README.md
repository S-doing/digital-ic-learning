# 异步 AXI4-Stream FIFO（async_axis_fifo）

## 1. 模块简介
本项目实现了一个基于 AXI4-Stream 协议的**异步 FIFO（跨时钟域缓冲）**。
写端（Write Domain）与读端（Read Domain）使用完全独立的时钟（`s_clk` 和 `m_clk`）与复位信号。模块内部采用**格雷码（Gray Code）指针**以及**多级触发器同步器**，完美解决了读写指针跨时钟域传输时的亚稳态问题。

主要特性：
- 纯正的异步双时钟设计，支持任意频率比例的跨时钟域数据传输
- 采用格雷码编码指针，保证跨时钟域时每次仅 1 bit 翻转，消除亚稳态
- 支持 AXI4-Stream 标准反压（tvalid/tready 握手）
- 完全参数化设计，数据位宽与 FIFO 深度可自由配置
- 组合逻辑读 RAM，保证数据与 `tvalid` 握手信号同拍有效

## 3. 模块说明

### 3.1 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `DATA_WIDTH` | 8 | 每个数据字的位宽 |
| `FIFO_DEPTH` | 16 | FIFO 深度（必须为 ≥ 4 的 2 的整数次幂） |
| `PTR_WIDTH` | 自动 | `$clog2(FIFO_DEPTH)`，地址指针位宽 |

### 3.2 端口

| 端口 | 方向 | 位宽 | 说明 |
|------|------|------|------|
| `s_clk` | input | 1 | 写时钟（源时钟域） |
| `s_rst` | input | 1 | 写端复位，**高电平有效** |
| `s_axis_tdata`  | input  | `DATA_WIDTH` | 写端数据 |
| `s_axis_tvalid` | input  | 1 | 写端数据有效 |
| `s_axis_tready` | output | 1 | 写端就绪（= 非满） |
| `m_clk` | input | 1 | 读时钟（目的时钟域） |
| `m_rst` | input | 1 | 读端复位，**高电平有效** |
| `m_axis_tdata`  | output | `DATA_WIDTH` | 读端数据 |
| `m_axis_tvalid` | output | 1 | 读端数据有效（= 非空） |
| `m_axis_tready` | input  | 1 | 读端就绪 |

## 4. 内部结构与工作原理

- **双端口 RAM**：使用寄存器数组 `fifo_buff` 实现。写操作同步于 `s_clk`，读操作采用纯组合逻辑输出（Read Combinational），保证 `m_axis_tdata` 无延迟。
- **指针位宽设计**：读写指针位宽为 `PTR_WIDTH + 1`。多出的最高位作为“翻转位（Wrap Bit）”，用于区分“空”和“满”。
- **跨时钟域同步（CDC）**：
  - 写端用 `s_clk` 对读指针的格雷码打两拍（`rd_gray_ptr_d0/d1`），用于判断 `fifo_full`。
  - 读端用 `m_clk` 对写指针的格雷码打两拍（`wr_gray_ptr_d0/d1`），用于判断 `fifo_empty`。
- **空满判断逻辑**：
  - **空（Empty）**：读指针格雷码与同步过来的写指针格雷码完全相等。
  - **满（Full）**：写指针格雷码与同步过来的读指针格雷码相比，最高两位不同（相反），其余低位完全相同。

## 5. AXI-Stream 握手协议
- 数据传输发生在 `tvalid && tready` 同时为高的时钟上升沿。
- **写握手**：`s_axis_tvalid && s_axis_tready`。只有 FIFO 未满时（`s_axis_tready=1`），写操作才会发生。
- **读握手**：`m_axis_tvalid && m_axis_tready`。只有 FIFO 非空时（`m_axis_tvalid=1`），读操作才会发生。
- 若接收端未准备好（`tready=0`），发送端的 `tvalid` 必须保持高电平且数据保持不变，直到握手成功。

## 6. 仿真验证说明 (Self-Checking)

`async_axis_fifo_tb.v` 使用了工业级的**自校验（Self-checking）**方法。读端模拟真实的下游模块，在握手成功时自动捕获数据，并与写入时的预期队列（`expected_mem`）进行实时比对，输出 `[PASS]` 或 `[ERROR]`。

### 测试环境
- **写时钟 `s_clk`**：50MHz（周期 20ns）
- **读时钟 `m_clk`**：200MHz（周期 5ns），产生 4 倍的极速频率差。
- **测试数据**：`$random` 随机数。

### 测试用例
| 测试项 | 操作与检查点 |
|--------|--------|
| **Test 1**：基本写入与读出 | 写入 10 个随机数据，开启读端消费，验证数据能否跨越时钟域完美复现。 |
| **Test 2**：Full 反压测试 | 写端连续写入 50 个数据（远超深度 32）。验证满标志触发时 `s_axis_tready` 正确拉低，写端挂起等待，**绝对不丢包**。 |
| **Test 3**：Empty 保护测试 | 将 FIFO 读空后，强行将 `m_axis_tready` 拉高。验证 `m_axis_tvalid` 严格保持低电平，不输出无效数据。 |
| **Test 4**：并发异步读写 | 使用 `fork...join`，让写端（慢时钟）和读端（快时钟）同时进行高强度的读写并发，验证格雷码跨时钟域的极限稳定性。 |

## 7. 已知问题与扩展限制
- **读数据组合逻辑延迟**：由于使用了组合逻辑读 RAM，若将 `FIFO_DEPTH` 设置得非常大（如 1024 以上），综合工具会将其推断为 BRAM，导致读数据天然带一拍延迟。此时需将读出逻辑改为时序逻辑，并相应调整 AXI 握手时序。
- **复位类型**：当前代码采用**同步复位**。在极高频或极端工业环境下，建议升级为“异步复位，同步释放”架构。
- **深度限制**：`FIFO_DEPTH` 必须为 2 的幂，且建议 ≥ 4，否则格雷码跨时钟域无法生效。
